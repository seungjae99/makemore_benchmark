NLL = Negative Log-Likelihood. Measures how surprised the model is by each held-out bigram — lower means better predictions.
NLL = −(1/N) Σ log P(ch₂ | ch₁)  ← averaged over all bigrams in test set
Why is the neural model slightly worse?
1
Under-trained: only 100 epochs with a fixed lr=50. The model hasn't fully converged to the optimal bigram distribution.
2
L2 over-regularization: λ=0.01 pushes weights toward zero, slightly distorting the learned probabilities.
3
Count-based has the right prior: Laplace smoothing (+1) is a provably optimal regularizer for bigram frequency estimation from discrete data.

Key Takeaways
Count-based wins on both dimensions. It is ~2× faster AND has lower test NLL (2.4511 vs 2.4712). At bigram scale, a smoothed frequency table is the optimal approach.
The neural model's accuracy gap is fixable. More epochs, a decaying learning rate, or tuned L2 would close the 0.02 NLL gap — but it still can't beat the count model's speed.
Autograd overhead is small at this scale. no_grad saves 19% — the matmul + exp dominates, not bookkeeping.
Neural pays off when the architecture grows. Once context window > 1 (MLP / Transformer), a lookup table is no longer feasible — that's where neural wins.
